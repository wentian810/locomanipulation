# FoundationPose++ 调参指南

## 术语表

### KF 相关

| 术语 | 含义 | 物理类比 |
|------|------|---------|
| **信任测量** | KF 用一个低噪声参数表示"这个传感器很准"，测量中单位误差会产生较大的状态修正 | 完全信 GPS → GPS 跳 1 米位姿就跳 1 米 |
| **不信任测量** | KF 用一个高噪声参数表示"这个传感器不太准"，测量误差被 KF 自己过滤掉 | 不信 GPS → GPS 跳 1 米只修正 0.2 米 |
| **预测占主导** | KF 更相信自己根据速度/加速度推算出来的位置（平滑但有惯性） | 惯性导航为主 |
| **测量占主导** | KF 更相信传感器实时读数（响应快但可能抖） | GPS 为主 |

### 模块触发相关

| 术语 | 含义 |
|------|------|
| **容易触发** | 阈值更接近正常值 → 小异常就激活切换 |
| **难以触发** | 阈值远离正常值 → 必须明显异常才激活 |
| **更快恢复** | 丢失后更少的帧数就触发 CutieReset |

## 核心参数详解

### 1. `--kf_measurement_noise_scale`（KF 测量噪声，命令行可调）

**作用**：控制 KF 对 `track_one` 6D 测量结果的信任度。

```
正常范围: 0.02 ~ 0.20
```

| 调大 | 调小 |
|------|------|
| 更信 KF 自身预测 → 轨迹更平滑 | 更信 track_one 测量 → 响应更快 |
| 高动态场景可能跟丢 | 静态场景可能抖动 |
| 遮挡恢复更慢 | Cutie 每像素抖动直接进入位姿（更信测量→噪声不衰减） |

**典型值**：稳定场景 `0.02-0.05`，动态场景 `0.08-0.15`。

---

### 2. 卡尔曼滤波器内部噪声（需改源码 `kalman_filter_6d.py`）

#### 2.1 `_std_weight_trans_xy`（Cutie xy 测量噪声，line 37）

**作用**：控制 KF 对 Cutie bbox 中心的信任度。

```
默认: 1/40 ≈ 0.025
正常范围: 1/80 ~ 1/10
```

| 调大（如 1/20） | 调小（如 1/80） |
|-----------------|-----------------|
| KF 更不信任 Cutie → 位姿更平滑 | KF 更信任 Cutie → Cutie 误差在 KF 中衰减较少 |
| Cutie 像素抖动被过滤掉 | 高动态时响应更快 |
| 快动可能滞后 | 静态可能抖动 |

**重要**：此噪声会被 `scale_xy = max(norm(tx,ty), tz*0.2)` 缩放。物理含义：Cutie 1 像素误差 ≈ `tz/fx` 米/px。

#### 2.2 `_std_weight_vel_trans`（速度不确定性，line 41）

**作用**：KF 每帧 predict 时假设速度有多少不确定性。越大 = 越不相信匀速假设。

```
默认: 1/20 = 0.05
正常范围: 1/40 ~ 1/5
```

| 调大（如 1/10） | 调小（如 1/40） |
|-----------------|-----------------|
| KF 预测权重降低 → 更信测量 | KF 预测权重提高 → 更平滑 |
| 加速运动跟踪更好 | 静态/匀速更稳定 |
| 静态场景可能抖动 | 快动可能跟丢 |

#### 2.3 `_std_weight_vel_rot`（旋转速度不确定性，line 42）

**作用**：同上，针对旋转分量。

```
默认: 1/40 = 0.025
正常范围: 1/80 ~ 1/20
```

| 调大 | 调小 |
|------|------|
| 旋转变化时 KF 更信任测量 → 响应更快 | 旋转更平滑但有惯性（KF 预测占主导） |

#### 2.4 `_std_weight_trans`（track_one 平移测量噪声，line 39）

**作用**：KF 认为 track_one 平移结果有多准。

```
默认: 1/10 = 0.1
正常范围: 1/20 ~ 1/5
```

| 调大 → track_one 测量被更不信任 → KF 预测权重更高 |
| 调小 → track_one 测量被更信任 → 响应更快 |

#### 2.5 `_std_weight_rot`（track_one 旋转测量噪声，line 40）

**作用**：同 2.4，针对旋转分量。

```
默认: 1/20 = 0.05
```

---

### 3. 运动检测（`obj_pose_track.py`）

#### 3.1 `HIGH_MOTION_THRESH`（高动态阈值，line 430）

**作用**：物体在图像上移动超过多少像素/帧才判定为高动态。

```
默认: 12.0 px/frame
正常范围: 5 ~ 30
```

| 调小（如 5） | 调大（如 25） |
|--------------|--------------|
| 更容易进入高动态模式 | 更难进入高动态模式 |
| 轻微运动就放大 KF 噪声 | 只有剧烈运动才响应 |
| 正常运动时 KF 噪声频繁切换 → 抖动 | 中速运动可能跟丢 |

#### 3.2 `MOTION_DECAY`（运动检测 EMA 衰减，line 429）

**作用**：运动信号平滑程度。

```
默认: 0.6
正常范围: 0.3 ~ 0.8
```

| 调小（如 0.3） | 调大（如 0.8） |
|----------------|----------------|
| 记忆短 → 运动停止后快速退出高动态 | 记忆长 → 运动停止后仍维持高动态 |
| 频繁切换模式 | 过渡平滑但滞后 |

#### 3.3 `set_process_noise_scale(3.0)`（高动态 KF 缩放，line 643）

**作用**：高动态时速度不确定性放大倍数。

```
默认: 3.0
正常范围: 1.5 ~ 5.0
```

| 调大（如 5.0） | 调小（如 1.5） |
|----------------|----------------|
| 高动态时更激进地跟随测量 | 高动态时仍保留一定平滑 |
| 噪声可能被放大 | 加速运动可能跟丢 |

---

### 4. 遮挡与恢复（`obj_pose_track.py`）

#### 4.1 `RE_REGISTER_THRESHOLD`（CutieReset 触发帧数，line 573）

**作用**：连续多少帧丢失（bbox 无效或无深度）后触发 Cutie 重初始化。

```
默认: 3
正常范围: 2 ~ 8
```

| 调小（如 2） | 调大（如 8） |
|--------------|--------------|
| 更快恢复，但可能误触发 | 更稳定，但遮挡后恢复慢 |
| 短暂遮挡就重置 Cutie | 长时间才重置，KF 可能漂移 |

#### 4.2 Cutie memory 污染阈值（line 569）

**作用**：物体完全可见但 Cutie bbox 面积 < 投影 bbox 面积 × 此阈值 → 判定记忆污染。

```
默认: 0.5（即 Cutie < 投影 50%）
正常范围: 0.3 ~ 0.7
```

| 调小（如 0.3） | 调大（如 0.7） |
|----------------|----------------|
| 只有严重记忆污染才触发 | 更容易触发（轻微缩水就重置） |
| 恢复慢 | 可能频繁重置 Cutie |

#### 4.3 深度采样窗口比例（line 547-548）

**作用**：在 bbox 中心采样深度时，采样窗口 = `max(最小, bbox尺寸 × 此比例)`。

```
默认: 0.15（15%）
最小半宽/半高: 2px
最小有效点数: 5
```

| 调大（如 0.3） | 调小（如 0.1） |
|----------------|----------------|
| 采样窗更大 → 更不容易误判遮挡 | 采样窗更小 → 更精确检测遮挡 |
| 可能包含背景深度（误判物体存在） | 远距离物体可能误判遮挡 |

#### 4.4 深度有效最小点数（line 556）

**作用**：采样窗内至少需要多少有效深度点才认为 bbox 有深度。

```
默认: 5
正常范围: 3 ~ 15
```

| 调小（如 3） | 调大（如 15） |
|--------------|--------------|
| 更容易判定为"有深度" | 更严格判定 |
| 误判较少，但可能漏掉真正遮挡 | 无深度区域不容易通过 |

#### 4.5 模糊帧污染检测阈值（line 531）

**作用**：高速运动 → 模糊 → SAM 把手+物体合并成一个 mask → Cutie bbox 异常大（包含手）。当 Cutie 面积 > 投影面积 × 此阈值 → 判定模糊污染 → 用投影中心替代 Cutie 中心。

```
默认: 2.0（Cutie > 投影 200% 触发）
正常范围: 1.5 ~ 3.0
```

| 调小（如 1.5） | 调大（如 3.0） |
|----------------|----------------|
| 更容易检测到手+物体合并 | 只有严重合并才触发 |
| 正常运动可能误触发 | 模糊帧可能漏过 |

**原理**：投影 bbox 基于真实 3D 尺寸 + KF 位姿，不受图像模糊影响。模糊帧的 Cutie bbox 比投影大 2 倍以上 → 不可能只是物体变大 → 一定是混入了手/背景。

---

### 5. FoundationPose refine 迭代（命令行）

#### 5.1 `--track_refine_iter`

**作用**：每帧 `track_one()` 的 refine 网络迭代次数。

```
默认: 5
正常范围: 2 ~ 10
```

| 调大 | 调小 |
|------|------|
| 位姿更精确 | 帧率更高 |
| 高动态可能跟不上（耗时增加） | 位姿精度下降 |

#### 5.2 `--est_refine_iter`

**作用**：首帧 `register()` 的 refine 迭代次数。

```
默认: 10
正常范围: 5 ~ 20
```

| 调大 | 调小 |
|------|------|
| 首帧位姿初始化更准 | 初始化更快 |
| 跟踪全程受益于更好的初始位姿 | 初始误差大可能全程偏 |

## 场景调参速查

### 场景 1：静态物体抖动

**症状**：物体不动，3D bbox 和坐标轴在抖动。

**原因**：KF 过度信任 Cutie → Cutie 每像素噪声直接传导到位姿。

**解决**：

| 优先级 | 操作 | 原理 |
|--------|------|------|
| ★★★ | 增大 `_std_weight_trans_xy`（1/40 → 1/25） | 降低 Cutie 权重 |
| ★★★ | 降低 `_std_weight_vel_trans`（1/20 → 1/40） | 加固 KF 预测 |
| ★★ | 增大 `--kf_measurement_noise_scale`（0.05 → 0.10） | 降低 track_one 权重 |
| ★ | 增大 `HIGH_MOTION_THRESH`（12 → 25） | 防止噪声触发高动态 |

---

### 场景 2：高动态跟不上

**症状**：快速移动时 bbox 落后于物体或跟丢。

**原因**：KF 预测权重过高 → 匀速假设在加速时失效。

**解决**：

| 优先级 | 操作 | 原理 |
|--------|------|------|
| ★★★ | 增大 `set_process_noise_scale`（3.0 → 5.0） | 高动态更激进 |
| ★★★ | 降低 `HIGH_MOTION_THRESH`（12 → 6） | 更早激活高动态 |
| ★★ | 增大 `_std_weight_vel_trans`（1/20 → 1/10） | 基础过程噪声也放大 |
| ★★ | 减小 `_std_weight_trans_xy`（1/40 → 1/60） | 更信任 Cutie 响应 |
| ★ | 降低 `--track_refine_iter`（5 → 3） | 减少每帧耗时 |

---

### 场景 3：遮挡后恢复很差（bbox 偏小、位姿漂移）

**症状**：手遮过后 bbox 长时间无法包围物体，bbox 偏小。

**原因**：遮挡期间 KF 只 predict → 速度分量被污染 → 恢复后漂移不消除。

**解决**：

| 优先级 | 操作 | 原理 |
|--------|------|------|
| ★★★ | 降低 `RE_REGISTER_THRESHOLD`（3 → 2） | 更快触发 CutieReset |
| ★★ | 增大深度采样窗口比例（0.15 → 0.25） | 减少假遮挡误判 |
| ★★ | 降低深度有效最小点数（5 → 3） | 更不容易误判遮挡 |
| ★ | 减小 Cutie 污染阈值（0.5 → 0.4） | 更早检测到记忆污染 |

---

### 场景 4：换相机视角后抖动

**症状**：换个相机角度后，静态抖动变大。

**原因**：`scale_xy = max(norm(tx,ty), tz*0.2)` —— 物体在图像中心时 `norm(tx,ty)≈0`，由 `tz*0.2` 保护。若仍抖，说明 0.2 不够大。

**解决**：

| 优先级 | 操作 | 原理 |
|--------|------|------|
| ★★★ | 增大 `scale_xy` floor 系数（0.2 → 0.4） | 提高 Cutie 噪声下限 |
| ★★ | 增大 `_std_weight_trans_xy`（1/40 → 1/30） | 全局降低 Cutie 权重 |

---

### 场景 5：物体远离相机 → bbox 太小、频繁误判遮挡

**症状**：物体离远后 bbox 很小（~30-50px），深度采样窗不足，被误判为遮挡。

**原因**：深度采样最小窗口固定为 2px，比例 0.15 → 采样窗 = 15-25 px² → 可能不满 5 个有效深度。

**解决**：

| 优先级 | 操作 | 原理 |
|--------|------|------|
| ★★★ | 深度采样最小窗口 2 → 5 | 保证至少 100px² 采样窗 |
| ★★ | 深度有效最小点数 5 → 3 | 降低要求 |
| ★ | 增大深度采样比例 0.15 → 0.25 | 扩大采样窗 |

---

### 场景 6：实时性要求高（需要更高帧率）

**解决**：

| 操作 | 代价 |
|------|------|
| 降低 `--track_refine_iter`（5 → 2 或 3） | 位姿精度略降 |
| 降低 `--est_refine_iter`（10 → 5） | 首帧初始化精读略降 |

---

### 场景 7：Mesh 尺寸不准确（bbox 整体偏大/偏小）

**症状**：不管怎么调 KF 参数，3D bbox 始终看起来比实际物体大/小。

**原因**：这不是参数问题，是 `real_dims.json` 或 mesh 尺寸不对。

**解决**：
1. 删除 `real_dims.json` + `mesh_cache.json` + `mesh/` 目录
2. 确保首帧 mask 准确包围物体（没有手遮挡、没有背景杂点）
3. 重新跑 pipeline Step 4-5

---

### 场景 8：`[CutieReset]` 频繁打印

**症状**：日志中 CutieReset 频繁出现，bbox 大小反复跳变。

**原因**：遮挡检测阈值太接近正常值，Cutie 微小波动即触发重置 → 频繁切换。

**解决**：

| 优先级 | 操作 | 原理 |
|--------|------|------|
| ★★★ | 增大 `RE_REGISTER_THRESHOLD`（3 → 5） | 提高触发门槛，减少误触发 |
| ★★ | 增大 Cutie 污染阈值（0.5 → 0.35） | 更严重的污染才触发 |
| ★ | 检查 mask_vis 图像 → 确认 Cutie mask 是否正常 |

---

### 场景 9：高速移动时 bbox/坐标轴飘到手上

**症状**：快速移动时，3D bbox 突然偏离物体跳到手上，随后又回来。mask_vis 显示该帧 mask 包含了手+鼠标整体。

**原因**：高速运动 → 运动模糊 → SAM 无法区分手和鼠标 → 输出合并 mask → Cutie bbox 为手+鼠标总区域 → 中心偏到手的位置 → KF 被错误中心拉偏。

**代码机制**：`obj_pose_track.py` line 531 已内置模糊帧检测——当 Cutie bbox 面积 > 投影 bbox 面积 × 2.0 时，自动用投影中心替代，无需额外操作。该阈值对应参数 4.5。

**解决**（如果默认值不够，需要调整）：

| 优先级 | 操作 | 原理 |
|--------|------|------|
| ★★★ | 降低模糊污染阈值（2.0 → 1.5） | 更早检测到手+物体合并 |
| ★★ | 检查 mask_vis → 确认模糊帧中 mask 包含手+物体 |

**效果**：检测到污染 → 该帧用投影中心（基于 KF 预测位姿 + real_dims）→ bbox 不飘到手上 → 帧过了 Cutie 恢复正常。

## 快速诊断流程

```
问题: bbox 抖动?

  1. 物体在动?
     YES → 场景 2（高动态跟不上）或场景 8（频繁切换模式）或场景 9（飘到手上）
     NO  → 场景 1（静态抖动）或场景 4（相机视角）

  2. bbox 是否跳到手上?
     YES → 场景 9（模糊帧+合并 mask）
     NO  → 继续

  3. 什么相机视角?
     同之前 → 场景 1
     新视角 → 场景 4

问题: 遮挡后有异常?

  3. bbox 大小?
     偏小 → 场景 3
     正常 → 可能是位姿漂移 → 场景 3

  4. 物体距相机多远?
     远(bbox<50px) → 场景 5
     近(bbox>100px) → 场景 3
```
